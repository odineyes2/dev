# 변경 영역 중심 검사 정책 (DEV-261)

2026-11-20 사용자 직접 지시로 이전 DEV-259의 전체 검사·all 전환 제안을 폐기한다. 전체 화면·전체 사이트 캡처와 전체 화면 회귀 검사는 실행하지 않는다. 공통 CSS 변경이나 영향 범위가 불명확해도 전체 검사로 확대하지 않는다.

## 실행 범위

- 변경한 동작과 이를 직접 사용하는 영역만 확인한다. 예: 계정 메뉴 변경은 계정 메뉴, 배우 필터 변경은 스튜디오 필터·결과·상세 연결만 방문한다. 밤·낮이나 모바일 차이가 이번 변경에 영향을 받는 경우에만 그 조합을 포함한다.
- 새 계획은 모든 검사에 `## 검사 입력`을 선언한다. `cmd`, `phase`, `inputs`, `conditions`, `reuse`가 필요하며 `conditions.scope`는 구체적인 동작·영역 목록이다. 문서만 바꾸면 `없음 — 이유`를 쓴다.
- static → functional → browser 순서로 실행하며 같은 단계 안에서도 실패 즉시 뒤 검사를 중단한다. 구형 무계약 검사는 기능 단계로 처리하고 알려진 디자인 정적 검사는 먼저 실행한다.
- 기존 `scripts/screens.py`·`screenshots.*` 전체 실행기, 전체 선택자, 이를 부르는 npm 별칭은 서버 실행 경로에서 차단한다. 기존 승인 계획의 금지된 명령은 `policy_skipped`로 표시하며 실행·통과와 구별한다. 새 계획에는 금지 명령을 등록할 수 없다.
- 실행 프롬프트에도 같은 금지를 전달한다. 프로젝트 AGENTS.md의 오래된 전체 캡처 의무를 최신 사용자 지시로 대체한다. 다른 스크립트에 전체 실행기를 숨겨 호출하지 않는다.
- 서버는 승인된 좁은 검사를 임의로 더하거나 전체 검사로 대체하지 않는다. 범위가 불명확하면 필요한 동작을 특정해 계획을 보완한다.

## 유효성·취소

- 동일한 승인·입력·환경과 결정적 fixture가 선언된 성공 결과만 재사용한다. 재사용을 위해 실패를 통과로 바꾸지 않는다.
- Chromium 런타임 로그·검증 마커는 의존성 바이트가 아니다. 알려진 런타임 파일은 환경 해시에서 제외하며 실제 설치 바이너리·라이브러리 변경은 계속 감지한다.
- 입력 변경 시 파일 목록, 설치 파일 목록, 환경 구성요소의 변경을 남긴다. 환경변수 값이나 비밀값은 출력하지 않는다.
- 소유 실행이 종료되거나 시간 한도에 도달하면 진행 중인 검사 프로세스 트리를 종료하고 뒤 검사를 시작하지 않는다.
- 캡처는 이번 검사에서 실제 생성·변경된 파일만 결과에 보관한다. 이전 Task의 대량 캡처를 매 검사마다 복사하지 않는다.

## 한계

명령·npm 별칭·계획 계약에 대한 Dev의 실행 정책이며, 임의 코드가 모든 화면을 방문하는지를 정적으로 증명하는 OS 샌드박스는 아니다. 실행 에이전트도 명시한 범위만 구현해야 한다. 별도 프로젝트의 실제 유료 API·데이터 보호 규칙은 그대로 적용한다.
