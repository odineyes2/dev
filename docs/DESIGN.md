# 디자인 방향 — dev · nightshift 공통

> 이 문서가 두 프로젝트의 화면을 지배한다. 화면을 만들거나 고치는 에이전트는 **작업 전에 이 문서를 읽고**,
> 끝낼 때 "어느 절을 따랐는지"를 이슈 메모에 적는다. 문서와 다르게 해야 할 이유가 생기면 코드보다 **이 문서를 먼저 고친다**
> (고친 이유는 맨 아래 "결정 기록"에). DEV-10, 2026-09-30.

## 1. 한 줄 방향

**"밤의 작업실"** — nightshift의 정체성(초승달, 모노·대문자·넓은 자간의 틀 글자, 어두운 밤 톤)을 두 프로젝트가 가족처럼
공유하고, 그 위에 Linear 같은 **차분하고 현대적인 도구 UI**를 입힌다. 화려함보다 **정돈·속도·또렷함**.

- 차분함: 색은 거의 무채색, 색은 **상태와 주요 동작에만**.
- 여유: 촘촘하게 욱여넣지 않는다. 대신 한 화면에 할 일이 분명하다.
- 반응: 누르면 바로 반응한다(움직임은 짧고, 기다림은 보이게).
- 같은 것은 같게: 같은 역할의 요소는 두 프로젝트에서 같은 모양·같은 이름.

## 2. 글자

글자는 역할이 둘이다 — 섞지 않는 게 요점이다.

| 역할 | 글꼴 | 모양 | 쓰는 곳 |
|---|---|---|---|
| **틀 글자** | IBM Plex Mono(한글은 Pretendard로 대체) | 대문자, 600, 넓은 자간 | 로고, 전역 탭, 섹션 제목, 표 머리, 필드 이름, ID·시간·버전 같은 메타 |
| **내용 글자** | Pretendard Variable | 보통 대소문자, 400~650, 자간 -0.005 ~ -0.02em | 제목, 본문, 댓글, 버튼 글자, 상태 이름, 입력 |

- 자간 토큰: `--track-brand .24em`(로고) · `--track-nav .14em`(탭) · `--track-label .12em`(라벨·섹션 제목).
- 글자 크기 단계(이것만 쓴다): **11 · 12 · 13 · 14 · 16 · 20 · 24px**. 11px는 틀 글자 전용, 본문은 14, 조밀한 목록은 13.
  반 픽셀(10.5, 11.5, 12.5 …)은 새로 쓰지 않는다 — 기존 것은 고칠 때 가까운 단계로 옮긴다.
- 굵기: 400(본문) · 500(목록 제목·버튼) · 600(틀 글자·강조) · 650(페이지 제목). 700 이상은 쓰지 않는다.
- 줄 높이: 본문 1.6~1.7, 한 줄 UI 1.4.
- 숫자가 나란히 바뀌는 곳(진행률·시간·금액)은 `font-variant-numeric: tabular-nums`.

## 3. 색

nightshift `01-base.css`의 값이 원본이다. 두 프로젝트가 같은 토큰 이름을 쓴다(아래 이름으로 맞춰 간다).

| 토큰 | 낮 | 밤 | 쓰임 |
|---|---|---|---|
| `--bg` | #F7F8FA | #14161B | 바탕 |
| `--panel` | #FFFFFF | #1C1F26 | 카드·패널·헤더 |
| `--panel-2` | #F2F4F7 | #22262E | 호버, 표 머리, 코드 바탕, 칸반 열 |
| `--border` | #E3E6EB | #2C3038 | 1px 선 |
| `--text` | #1B1F24 | #E7E9ED | 본문 |
| `--text-dim` | #6B7280 | #97A0AC | 보조 글자(흰 바탕 4.8:1 — 작은 글자는 이것 이상) |
| `--accent` | #2563EB | #6D9BFF | 주요 동작·선택·링크 |

상태색(점·배지·밑줄에만, 넓은 면을 칠하지 않는다):

| 의미 | 색 | nightshift | dev |
|---|---|---|---|
| 대기·예정 | 회청 #98A2B3 / 파랑 | queued | backlog |
| 진행 중 | 주황 #B45309 | running | in_progress |
| 검토·확인 | 파랑 #2563EB | — | in_review |
| 완료 | 초록 #15803D | done | done |
| 실패·위험 | 빨강 #DC2626 | failed | changes_requested |
| 중단·보류 | 보라 #7C3AED / 회색 | interrupted | triage / on_hold |

- 주요 버튼만 대각선 그라데이션(`--grad-primary`). 위험 동작은 빨강 글자·테두리, 꽉 찬 빨강은 되돌릴 수 없는 확인 단계에서만.
- 밤 모드는 색을 뒤집는 게 아니라 **바탕 계열만** 바꾼다. 상태색·그라데이션은 그대로. `color-scheme`을 같이 준다.
- 밤/낮은 두 상태 토글(달↔해). 고른 적 없으면 운영체제를 따른다.

## 4. 간격·모서리·그림자

- 간격 단계: **4 · 8 · 12 · 16 · 24 · 32px**(`--sp-1…6`). 카드 안쪽 16~24, 섹션 사이 24, 페이지 여백 28(모바일 14).
- 목록 한 줄 높이 44~46px, 표 머리 38px. 터치 기기의 누르는 자리는 **최소 40×40**.
- 모서리 단계: **6(작은 것·입력·버튼) · 8(카드·패널·표) · 12(모달·큰 카드) · 999(필·칩·토글)**. 4·5·10·20px은 새로 쓰지 않는다.
- 그림자: 평소엔 거의 없음(`0 1px 2px rgba(16,24,40,.04)`), 떠 있는 것(메뉴·모달·토스트·끌고 있는 카드)만 `0 8px 24px rgba(16,24,40,.12)`.
  밤 모드는 그림자 대신 선으로.

## 5. 움직임

- 길이: 호버·색 **120~150ms**, 펼치기·접기 **200~280ms**, 화면 전환은 없음(바로).
- 곡선: `ease` 또는 `cubic-bezier(.2,.8,.2,1)`. 튕기는 효과는 쓰지 않는다.
- 움직여도 되는 것: 색, 투명도, 작은 이동(≤4px), 너비(탭 제목 펼침). **레이아웃을 크게 흔드는 애니메이션은 금지.**
- `prefers-reduced-motion: reduce`면 끈다.
- 테마를 바꿀 때 전환 애니메이션이 한꺼번에 돌지 않게 한다(필요하면 잠깐 transition을 끈다).

## 6. 아이콘

- **lucide**(선 2px, 둥근 끝) 한 가지만. 스프라이트 `<symbol id="i-이름">` + `<svg class="ico"><use href="#i-이름"/></svg>`.
- 크기: 글자 옆 1.2em, 탭 17px, 작은 버튼 14~15px.
- 아이콘만 있는 버튼은 반드시 `title`과 `aria-label`.
- 이모지·글자 기호(◐ ☾ ⎋ 등)를 아이콘 대신 쓰지 않는다.

## 7. 레이아웃 골격 (두 프로젝트 같음)

1. **헤더** — 왼쪽 초승달 + 워드마크(틀 글자), 오른쪽 사용자 칩(아이콘·이름·ADMIN) + 필 토글들. 칩을 누르면 계정 메뉴/창,
   맨 아래에 **다른 프로젝트로 가기**(dev ↔ nightshift).
2. **전역 탭 줄** — 아이콘 탭(마우스를 올리면 제목이 펼쳐짐), 활성은 파랑 밑줄, 성격이 다른 묶음 사이는 세로 구분선.
   오른쪽 끝에 그 화면의 전역 필터·주요 동작(예: 프로젝트 필터, + New).
3. **범위 줄**(필요할 때) — 한 대상 안에 들어갔을 때(워커 하나, 프로젝트 하나) 그 대상 이름과 **서브탭**.
4. **본문** — 최대 폭 1180~1320px, 도구줄(검색·필터 칩) → 목록/카드.

- **모달보다 서브탭**: 한 대상의 설정·상세처럼 오래 머무는 화면은 모달이 아니라 그 대상의 서브탭으로 둔다. 모달은 짧은 확인·
  한 가지 입력(만들기, 이유 묻기)에만.
- 좁은 화면(≤800px): 탭은 아이콘만·가로 스크롤, 사이드 패널은 아래로, 버튼 글자는 아이콘만(`hide-m`). 가로 스크롤이 생기면 버그.

## 8. 컴포넌트 규칙

| 요소 | 규칙 |
|---|---|
| 버튼 | 주요(그라데이션, 화면당 1개) · 보조(테두리) · 고스트(투명, 도구줄) · 위험(빨강 글자). 저장 중엔 **막고**(두 번 저장 방지) 글자를 "저장 중…"으로 |
| 스위치 | 켜고 끄는 설정은 체크박스가 아니라 **스위치**(`role="switch"`, `aria-checked`). 켜짐=초록 |
| 칩·필터 | 필 모양, 켜지면 accent 옅은 바탕 + accent 글자 |
| 상태 | 색 점 + 상태 이름(내용 글자). 글자만 색칠하지 않는다 |
| 카드 | 1px 선 + 옅은 그림자, 호버 시 선 진하게. 카드 전체가 눌리면 카드 안 버튼은 `stopPropagation` |
| 표 | 머리는 틀 글자, 줄 호버는 `--panel-2`, 누르면 상세 |
| 입력 | 포커스 링 `0 0 0 3px rgba(accent,.15)`, 자리표시 글자는 예시로("예: NS-3과 중복") |
| 빈 상태 | 점선 테두리 상자 + 한 줄 설명 + (있으면) 다음 행동 버튼 |
| 기다림 | 0.3초 넘으면 표시: 목록은 **스켈레톤**, 버튼은 도는 아이콘, 긴 일은 진행률 + "눌러서 진행 보기" |
| 알림(토스트) | 아래 가운데, 3초, 되돌릴 수 있으면 "되돌리기" 버튼 |
| 확인 | 되돌릴 수 있는 건 묻지 않고 되돌리기를 준다. 되돌릴 수 없는 것(지우기·돈 드는 것)만 확인창, 이유가 필요하면 입력창 |

## 9. 더 현대적으로 — 앞으로 들일 것 (우선순위순)

1. **스켈레톤 로딩** — 목록·카드가 빈 화면에서 툭 나타나지 않게.
2. **낙관적 반영 + 되돌리기 토스트** — 상태 바꾸기·지우기를 바로 반영하고 "되돌리기"를 준다(확인창을 줄인다).
3. **세그먼트 컨트롤** — 2~4개 중 하나 고르기(목록/칸반, 밤/낮/자동 같은 것)는 셀렉트 대신.
4. **명령 팔레트(Ctrl+K)** — 이슈·워커·프로젝트로 바로 가기, 새로 만들기.
5. **인라인 편집** — 제목·라벨은 누르면 그 자리에서 고친다.
6. **끈적한 도구줄** — 긴 목록에서 검색·필터가 위에 붙어 있게.
7. **키보드 단축키** — `c` 새로 만들기, `/` 검색, `g i` 이슈로 등(도움말은 `?`).

새 요소를 들일 때는 한 프로젝트에서 먼저 만들고, 잘 되면 이 문서의 8절에 규칙으로 올린 뒤 다른 프로젝트에 옮긴다.

## 10. 말투

- 화면 문구는 존댓말 "~해요". 짧게, 무엇을 하면 되는지로 끝낸다("…했어요 — 새로고침해 보세요").
- 용어는 한 프로젝트 안에서 하나로: nightshift는 **워커**(기록)·**파드**(실제 기계), dev는 영어 표준(Issue·Plan·Task·Agent).
- 오류는 원인 + 다음 행동. 코드나 스택을 그대로 보여 주지 않는다(자세히는 로그·상세에).

## 11. 접근성 최소선

- 대비: 본문·작은 글자 4.5:1 이상(`--text-dim` 이상), 큰 글자 3:1.
- 키보드: 모든 동작에 닿을 수 있고, `:focus-visible` 링이 보인다.
- 스크린리더: 아이콘 버튼 `aria-label`, 스위치 `role="switch"`, 메뉴 `role="menu"`.
- 색만으로 뜻을 전하지 않는다(상태는 점 + 글자).

## 12. 에이전트가 화면을 고칠 때의 절차

1. 이 문서를 읽고, 이번 작업에 해당하는 절을 이슈 계획서에 적는다.
2. 새 값을 만들지 않는다 — 토큰·단계 안에서 고른다. 없으면 이 문서에 먼저 추가한다.
3. 끝나면 **낮·밤 × 데스크톱(1300)·모바일(390)** 네 장을 찍어 직접 본다. 가로 스크롤·잘림·겹침이 없어야 한다.
4. 필요하면 `design-critique`로 평가하고 고친다.
5. 이슈 메모에 "따른 절", 캡처로 확인한 것, 이 문서를 고쳤으면 그 내용을 적는다.

## 13. 지금 두 프로젝트의 차이 — 맞춰 갈 것

| 항목 | nightshift | dev | 맞출 방향 |
|---|---|---|---|
| 토큰 이름 | `--text-dim`, `--queued`… | `--dim`, `--accent`… | 3절 이름으로(점진적으로, 고치는 김에) |
| 글자 크기 | 9.5~14px 반 픽셀 단계 10여 개 | 대체로 단계 안 | 2절 단계로 |
| 모서리 | 4·5·6·8·10·12·20·999 | 6·8·12·999 | 4절 단계로 |
| 설정 화면 | 워커 설정이 모달 | — | 서브탭으로(NS-9) |
| 로딩 | 대부분 빈 화면 → 표시 | 빈 화면 → 표시 | 스켈레톤(9절-1) |
